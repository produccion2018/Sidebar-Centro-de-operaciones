# Cloudster Dental Suite

Prompt para diseñar y organizar Cloudster — SaaS de gestión odontológica

Quiero que diseñes y organices visualmente el producto Cloudster, un SaaS profesional de gestión integral para clínicas odontológicas.

IMPORTANTE:

En esta etapa NO quiero backend.

NO quiero base de datos.

NO quiero autenticación real.

NO quiero APIs reales.

NO quiero desarrollar todavía la lógica empresarial.

Quiero principalmente el frontend/prototipo visual y funcional simulado.

Quiero poder navegar por las pantallas y entender visualmente cómo funcionaría cada módulo.

Utiliza datos ficticios/mock data para mostrar el funcionamiento.

Cada módulo debe parecer un software profesional real, no una simple tarjeta o página informativa.

Quiero una interfaz moderna, elegante, médica/odontológica, profesional y comercialmente atractiva.

Debe ser responsive para desktop, tablet y móvil.

La interfaz debe estar preparada para que posteriormente pueda conectarse a un backend real.

Si utilizas React, organiza el proyecto de manera modular y escalable.

DENTRO DE "APARIENCIA" — AGREGADO:

La sección Apariencia debe incluir un selector de tema de color para el sidebar/interfaz, no limitado a blanco o negro: ofrecer varias opciones de color (por ejemplo violeta —el color de marca por defecto—, azul, verde, amarillo, y algún tono oscuro/negro como alternativa). Este selector de tema es una función pensada para usuarios avanzados/administradores, no necesariamente expuesta de entrada a cualquier rol.

DENTRO DE "MÓDULOS" — AGREGADO (si no existe ya como sección propia, agregarla):

Crear un directorio/listado de todos los módulos del sistema, cada uno con un switch individual de activar/desactivar. El administrador debe poder prender o apagar módulo por módulo (por ejemplo: activar Inventario, desactivar Automatizaciones, activar RRHH, etc.), de forma independiente uno del otro — no en bloques fijos por plan únicamente, sino con control granular módulo por módulo dentro de lo habilitado por su plan. Mostrar visualmente el estado de cada módulo (activo/inactivo) y, si corresponde, un aviso de qué módulos requieren upgrade de plan para activarse.

FONDOS TEMÁTICOS POR MÓDULO — AGREGADO:

Cada módulo debe tener su propia imagen de fondo temática relacionada con su contenido, en vez de un fondo genérico repetido en toda la aplicación. Por ejemplo: el módulo de Recursos Humanos debe usar una imagen de fondo relacionada con RRHH/equipo de trabajo; el módulo de Inventario, una imagen relacionada con stock/insumos; el módulo de Facturación, una relacionada con documentos/pagos; y así sucesivamente, cada módulo con la imagen que le corresponda temáticamente. Estas imágenes van de fondo, sutiles (opacidad reducida), detrás del contenido principal de cada pantalla — nunca compitiendo visualmente con la información ni afectando la legibilidad.
